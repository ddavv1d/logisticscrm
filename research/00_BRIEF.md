# BRIEF — CRM для логистической компании (мультимодальные контейнерные перевозки)

> Единый источник правды для всех исследовательских агентов. Читай его первым.
> Дата: 2026-07-31. Заказчик: Давид. Язык интерфейса: русский.

## 1. Что мы строим
CRM-систему, которая **заменяет Excel** для логистической компании, возящей грузы в **контейнерах** по мультимодальному коридору «Средний коридор» (Middle Corridor / TITR):

```
Грузия (Тбилиси/Поти/Батуми)
  → [ж/д] → Азербайджан (Баку)
    → [паром/море, Каспий] → Туркменистан (Туркменбаши)
      → [ж/д] → Узбекистан (Ташкент)
        → [авто/ж/д] → далее по городам
```
Перевозка идёт **по плечам (legs)**: у каждого плеча свой вид транспорта (ж/д, паром, авто), свой перевозчик, свои сроки и своя стоимость.

## 2. Пользователи (3 роли)
- **Менеджер / диспетчер** — вводит ВСЕ данные, двигает стадии, пишет комментарии и расчёты. Главный ежедневный пользователь. Нужен максимально быстрый ввод.
- **Владелец / руководитель** — проверяет, берёт выгрузки (export), сверяется. В основном чтение + экспорт + дашборд «где деньги / где застряло».
- **Бухгалтерия / финансы** — учёт платежей и расчётов по каждому плечу; инвойсы; кто сколько должен; маржа.

## 3. КЛЮЧЕВОЕ требование по стадиям (прочитай внимательно — это ядро)
Заказчик дословно: «трекинг НЕ надо; надо чтобы просто СТАДИИ мог менять менеджер».

Это значит:
- НЕТ GPS, НЕТ карты в реальном времени, НЕТ интеграций с перевозчиками.
- Менеджер **вручную** переводит контейнер со стадии на стадию: «узнал, что груз в такой-то точке → выбрал стадию → сохранилось → показывается дальше».
- Каждое изменение стадии = запись в журнал с: **датой, временем, автором (кто менеджер), комментарием**.
- История стадий сохраняется и наглядно показывается (кто, когда, что изменил).
- Это паттерн **event-sourced status history / stage log** в максимально простом виде.

## 4. Модель груза (гибкая — менеджер сам выбирает)
Заказчик: «надо чтобы можно было и так и так; менеджер сам выберет».
- Вариант A: **1 контейнер = 1 груз/заказ клиента** (FCL, простой случай).
- Вариант B: **сборный груз (LCL)** — в одном контейнере грузы разных клиентов.
- **Начинаем с простого (A)**, но модель данных должна не мешать добавить B позже.

## 5. Что важно (приоритеты)
Всё равнозначно: **трекинг стадий + учёт груза + деньги/расчёты**. Это НЕ узкий трекер и НЕ только бухгалтерия — это рабочая операционная CRM.

## 6. Дизайн-принцип
«Невероятно наглядно, просто, без лишних сложностей, но функционал глубоко полезный».
- Владелец должен с одного взгляда понимать: где деньги, где застряло, сколько в пути.
- Менеджер должен вводить данные в 2-3 клика, без обучения.
